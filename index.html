What the demo proves

Less bandwidth

Step 2: the second user gets the file from Router 1’s Content Store in milliseconds, and the producer is never contacted.

Protection from overload

Steps 3 and 4: identical requests are merged by the Pending Interest Table, so ten requests cost the producer one.

Security in the data

Step 5: Data nobody asked for is dropped. Every real Data packet carries a signature that consumers verify, whichever node served it.

In IP networking, each of those requests would be a separate connection to one server address. NDN has no host addresses in its packets at all. Routing, caching and security all work on the content name.

Topology used: Consumer A (6001) and Consumer B (6002) connect to Router 1 (5001), then Router 2 (5002), then the Producer (5003), as UDP sockets on 127.0.0.1.

How each router decides

Content Store

LRU cache of Data packets, capacity 5, exact name match.

Pending Interest Table

Name to the ports waiting for it. Merges duplicates and records the way back. Entries expire after 10 seconds.

Forwarding Information Base

Name prefix to next-hop port, using longest-prefix match on whole name components.

Interest arrives

  1. Nonce already seen for this name? Drop and send NACK (LOOP).
  2. Name in the Content Store? Return the cached Data.
  3. Name in the PIT? Add this port and stop.
  4. FIB match? Record in the PIT and forward. Otherwise send NACK (NO_ROUTE).

Data arrives

  1. Name not in the PIT? Drop it as unsolicited.
  2. Verify the signature and store in the Content Store.
  3. Send to every port in the PIT entry, then delete the entry.

Packets carry names, not addresses

{
  "type": "INTEREST",
  "name": "/university/cs/notes/lecture1.pdf",
  "nonce": 482913

{
  "type": "DATA",
  "name": "/university/cs/notes/lecture1.pdf",
  "payload": "...file content...",
  "signature": "HMAC-SHA256(name + payload)"
}
